Partie 1 — Mode d'emploi

Avant de commencer

L'outil s'utilise dans le navigateur, sans installation. Il a besoin de deux choses :

1. La clé service
Saisie une seule fois dans config.html (elle donne le droit d'écrire en base). C'est la même clé que celle qu'utilise admin.html.
2. import.html en ligne
Le fichier doit être déployé sur GitHub Pages, à côté de admin.html (voir Déploiement). Ouvrir le fichier en local ne suffit pas : la clé n'y serait pas accessible.

Filet de sécurité — l'outil ne remplace jamais une valeur déjà saisie en base, et rien n'est écrit tant que tu n'as pas cliqué « Importer » après avoir vu l'aperçu.

Importer les articles Q2 — pas à pas

Exporter l'inventaire depuis Q2

Deux fichiers : l'inventaire consommable et l'inventaire locatif (format CSV, tel que Q2 le sort). Aucun nettoyage manuel n'est nécessaire.

Ouvrir import.html et rester sur le Mode 1

« Articles (inventaire Q2) » est sélectionné par défaut. La pastille de connexion en haut à droite confirme que la base est joignable.

Déposer les deux fichiers

Glisse-les dans la zone, ou clique pour les choisir. L'outil reconnaît tout seul lequel est consommable et lequel est locatif, et affiche le nombre de lignes lues.

Lire l'aperçu

Le tableau de synthèse s'affiche : combien d'articles seront créés, combien seront complétés, combien restent inchangés. Rien n'est encore écrit.

Vérifier puis lancer

Filtre sur « Nouveaux » pour contrôler quelques lignes, puis clique Importer dans Supabase et confirme. Une barre de progression et un journal détaillent l'opération.

Contrôler le résultat

Ouvre admin.html, recherche 2–3 réfs nouvellement créées et vérifie désignation / fournisseur / type. Au premier run, valide sur un petit lot avant de généraliser.

Comment lire l'aperçu

Chaque référence de l'inventaire est classée dans l'un de ces trois états :

Nouveau Absent de la base → sera créé
À compléter Existe déjà, mais des champs sont vides → seuls ces champs seront remplis
Inchangé Existe déjà et complet → l'outil n'y touche pas

Dans les lignes « À compléter », les valeurs affichées en orange sont précisément celles qui seront écrites. Les filtres et la recherche en haut du tableau permettent d'isoler un état ou une référence.

Bon à savoir — une référence présente à la fois dans le consommable et le locatif (cas connu) est comptée une seule fois : la version locatif est prioritaire.

Partie 2 — Notice technique

Architecture

Application d'une seule page (import.html), sans dépendance externe ni build. Elle parle directement à l'API REST de Supabase (PostgREST) avec la clé service_role.

URL base
localStorage.sb_url (défaut : projet kybdqgrikfevstkwzaqe)
Clé écriture
localStorage.sb_service — mêmes clés que admin.html
Lecture
GET /rest/v1/articles paginé par Range (lots de 1000)
Écriture
POST (upsert) et PATCH, header Prefer: return=minimal, resolution=merge-duplicates

Format d'entrée reconnu

L'outil absorbe le format brut sorti par Q2, sans conversion préalable :

  • Encodage — détection du BOM : UTF-16 LE / BE, sinon UTF-8. (Les exports Q2 sont en UTF-16 LE.)
  • Séparateur — tabulation détectée en priorité, puis ;, puis ,.
  • Guillemets Excel — les valeurs de type ="260528" sont nettoyées automatiquement.
  • Prix au format français — 1 499,00 → 1499.00 (espaces et virgule gérés).
  • Type de fichier — déduit de l'en-tête : colonne Code Article ⇒ locatif ; colonne Référence ⇒ consommable.

Validé le 08/07/2026 — 461 réfs consommables + 67 locatives lues correctement, 15 réfs communes, 513 réfs uniques (base : 495).

Mapping Q2 → référentiel

Une fiche article est reconstruite en dédoublonnant l'inventaire par référence. Seuls les champs « socle » sont alimentés ici ; le reste (codes-barres, AI, dimensions) est enrichi ensuite via le scan.

Pourquoi ne pas mettre la « Catégorie » Q2 dans categorie ? La colonne categorie a une contrainte stricte (Nutrition/Diabète/Parkinson). Les libellés Q2 (Patch, DIABETE-ADELIA…) la violeraient. Ils vont donc dans famille (texte libre), avec déduction de la catégorie quand c'est possible.

Logique de diff & d'écriture

Après lecture de la base, chaque référence est comparée et traitée différemment :

  • Nouveau → insert en lot (POST, paquets de 100) avec le jeu de colonnes complet.
  • À compléter → PATCH individuel ne portant que les colonnes actuellement vides. Une valeur déjà présente n'est jamais dans le payload, donc jamais écrasée.
  • Inchangé → aucune requête.
// existant : on ne complète que le vide
for (const k of fillable) {
  const curEmpty = isEmpty(cur[k]);
  if (curEmpty && !isEmpty(nouveau[k])) payload[k] = nouveau[k];
}

Le upsert utilise on_conflict=ref_q2 + resolution=merge-duplicates. Après import, le diff est recalculé automatiquement.

Migration 01 (prérequis Mode 2)

Le fichier MIGRATION_01_reconciliation_emplacements.sql se joue dans Supabase > SQL Editor, bloc par bloc. Non destructif sauf le bloc A-2 (commenté).

Bloc A
Corrige le doublon delai_appro_j / delai_appro_jours (rapatrie les valeurs, drop optionnel).
Bloc B
Table emplacements — référentiel de tous les emplacements, multi-site (IDF / ST-OUEN / REGION-…), avec code lisible calculé.
Bloc C
Table article_emplacement — lien article ↔ emplacement, type_stockage PICKING (1 par article) + MASSE (2ᵉ optionnel).
Bloc D
Vue v_article_emplacement + grants.

Rappel data — le successeur d'un article est déjà stocké en base (remplace_par text[]), et le prédécesseur dans remplace_ref. L'évolution « statut & remplacement visibles » est donc un travail d'affichage, pas de structure.

Déploiement (GitHub Pages)

  1. Aller sur le dépôt alwaysadelaro-rgb/idcare.
  2. Add file → Upload files → déposer import.html → Commit changes.
  3. Attendre 1–2 min, puis ouvrir …github.io/idcare/import.html.
  4. Vider le cache si besoin (Ctrl+Shift+R).

Un lien « 📥 Import masse » existe déjà dans le menu de admin.html : une fois le fichier en ligne, il cesse de renvoyer le 404 et pointe vers l'outil.

Limites connues & vigilance

  • Le consommable Q2 n'exporte pas de prix : ces articles sont créés sans prix_achat.
  • La « Catégorie » Q2 n'est pas toujours déductible en catégorie base ; famille reste la source fiable.
  • Les colonnes codes-barres / AI / dimensions ne sont pas alimentées par l'import : elles relèvent du scan dans admin.html.
  • L'écriture réelle en base dépend de la clé service_role et des droits RLS ; tester sur un petit lot au premier usage.
  • Le « Lieu » des exports (STOCK PNI IDF, STOCK SAINT OUEN…) est une cartographie de stocks par personne/région — distinct des emplacements rack du Mode 2.
